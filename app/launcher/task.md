Предлагаю сделать единый формат обмена статистикой между лаунчером и играми. При этом общая статистика будет рассчитываться самим лаунчером, а каждая игра будет передавать свои специфические показатели. Так мы не будем привязывать систему к конкретным играм и сможем добавлять новые без изменения общей структуры.
Формат хранения
Используем JSON в UTF-8. В пользовательской папке данных лаунчера будет находиться файл statistics.json, независимый от каталога установки и файлов игр.
{
  "schema_version": 1,
  "sessions": [
    {
      "session_id": "uuid-сессии",
      "game_id": "maze",
      "game_title": "Лабиринт",
      "started_at": "2026-10-16T12:00:00Z",
      "ended_at": "2026-10-16T12:12:30Z",
      "duration_seconds": 750,
      "status": "completed",
      "metrics": {
        "accuracy": {
          "label": "Точность",
          "value": 87.5,
          "unit": "%"
        },
        "errors": {
          "label": "Ошибки",
          "value": 3,
          "unit": "шт."
        }
      }
    }
  ]
}


Это пример одной сессии, а не фиксированный список всех допустимых показателей.
Какие данные собираем
А. Общая статистика
Формируется лаунчером автоматически на основании истории сессий.
- Общее количество тренировок.
- Суммарное время занятий.
- Количество запусков каждой игры.
- Дата последней тренировки.
- Активность по дням и неделям.


Б. Статистика конкретной игры
Передаётся самой игрой при завершении сессии.
- Время в игре и количество её запусков.
- Точность, ошибки, попадания и промахи.
- Время реакции, амплитуда движений, устойчивость.
- Любые другие показатели, предусмотренные конкретной игрой.


Протокол взаимодействия лаунчера и игры
При запуске лаунчер передаёт игре через переменные окружения:
Переменная	Назначение
MOVEUP_GAME_ID	Идентификатор игры
MOVEUP_SESSION_ID	Уникальный идентификатор тренировки
MOVEUP_STATS_FILE	Путь к файлу для передачи результатов
MOVEUP_STATS_SCHEMA_VERSION	Версия формата данных
Игра записывает в указанный файл результаты в JSON. Лаунчер считывает их после завершения процесса, проверяет идентификаторы и сохраняет в историю сессий.
Принципиальный момент: общую длительность сессии рассчитывает лаунчер по времени жизни процесса, а не доверяет значению времени, переданному игрой. Это позволяет получать сопоставимые данные от всех игр.
Сессии, прерванные аварийно или при закрытии лаунчера, должны иметь отдельный статус. Их нельзя автоматически считать успешно завершёнными тренировками.
